# insight.oracle-safety-check:v2 — cross-stack evidence vectors

Cross-stack fixtures for the `insight.oracle-safety-check:v2` evidence type
(issue `Agent-Authority-Conformance/aps-conformance-suite#26`, review
`aeoess/agent-passport-system#119`): an `OracleSafetyCheck` attestation
(Insight, EIP-712 schema v2, 26 signed fields) riding inside the APS
ReceiptV1 envelope as the evidence referenced by a policy-decision receipt's
`evidence_refs` (draft-pidlisnyi-aps §5.5).

Composite gate semantics (fail-closed): the pre-trade action proceeds **only
if** the authority half holds AND the oracle-safety evidence is authentic,
current and permitted. Any missing / expired / denied / unverifiable half is a
HALT.

**What this family checks on the authority half is enumerated, not assumed.**
The runner verifies each delegation's Ed25519 signature, its
`parent_delegation_id` linkage and issuer/subject continuity across the chain,
plus the leaf expiry (`not_after`) and declared revocation. It does **not** run
the SDK's full delegation-chain verification — authority attenuation (facet and
spend-limit narrowing, e.g. `SPEND_WIDENING`) is out of scope here.

Coverage is stated here in prose rather than in a `verification_mode` field:
that field already carries a different axis in this suite (its existing value
`record` describes the nature of the verification), and a machine-readable
coverage field, if one is wanted, is the maintainer's to define.

## Layout

```
oracle-safety-check-v1/    13 vectors + index.json (conformance format)
verify.ts                  runner: published SDK package + INNER layer truly
                           verified, semantic fields enforced
verify-consistency.ts      deterministic comparison that produces the 56/56
                           figure (four ABI-keccak commitments rebuilt from
                           oracle_input + positive digest/signature)
vendor/insight/            Insight OracleSafetyCheck v2 (EIP-712 + ABI-keccak),
                           byte-identical copy of the pinned source (SOURCE.md)
keys.ts                    deterministic key derivation (self-contained copy
                           of the upstream generator's rules)
```

Provenance: see [`SOURCE.md`](./SOURCE.md). The vectors are generated by the
**upstream generator** in `agent-passport-system`
(`fixtures/oracle-safety-check/generate-fixtures.ts`, PR #119) and copied here
per `docs/adding-vectors.md` — they are consumed with the **published** SDK
package (`agent-passport-system`), never deep imports into `src/`.

## Deterministic keypairs

Same public-seed convention as the rest of the suite extended for the four
roles this evidence type needs:

```
seed      = SHA-256("aps-oracle-safety-check-fixture-v1")
role_seed = SHA-256(seed_input || 0x00 || role)        role ∈ {principal, agent, gateway, evm-attester}
Ed25519   : private key = role_seed (RFC 8032 seed); public key = Ed25519 derivation
secp256k1 : private key = role_seed (scalar); address = keccak256(pubkey)[-20:]
```

No secret material anywhere; every implementation reproduces the same keys
from `seed_input`.

## Vector contract

The runner checks exactly the items listed below, plus the sub-results each
vector declares for itself. Nothing here claims to be the SDK's full
verification:

- **Checked:** each delegation signature, parent linkage and issuer/subject
  continuity; leaf expiry (`not_after`) and declared revocation; the inner
  EIP-712 digest, signer recovery against `roles.evm_attester.address`, and the
  rebuild of the oracle data from `oracle_input`; the composite-gate reason set.
- **Not checked:** authority attenuation (facet and spend-limit narrowing, e.g.
  `SPEND_WIDENING`). The SDK's full delegation-chain verifier
  (`verifyAuthorityDelegationChain`, which is what reports it) is not reachable
  from the published package: `agent-passport-system` 4.5.1 exports only `.` and
  `./core`, neither of which re-exports it, and `dist/src/**` is blocked by the
  package `exports` map. Deep-importing `src/` was ruled out in review #119.
- **Not exercised:** replay and single-use enforcement, which are stateful.
- `not_before` is not enforced, so there is no not-yet-valid negative vector.

The runner (`verify.ts`) enforces:

| Field | What the runner MUST check |
|---|---|
| `expected` | must be exactly `allowed` or `halt`; `allowed` ⇔ the derived composite-gate reason set is empty |
| `expectReasons` | the derived reason set must **exactly equal** the declared list (e.g. `halt` + `["HALT_ORACLE_EVIDENCE","UID_MISMATCH"]`). Flipping/emptying/adding codes FAILS the run |
| `oracle_input.verdict` | drives the verdict gate (`DANGER`→`HALT_VERDICT_DANGER`, `BLOCK`→`HALT_VERDICT_BLOCK`, `PASS`/`CAUTION`→permitted) and must faithfully rebuild the envelope data |
| `oracle_input` (rest) | the runner REBUILDS the full 26-field data (incl. the four ABI-keccak commitments) from it and compares with `envelope.oracle.data` |
| `expected_sub_results` | the named sub-results the runner must OBSERVE for this vector — this is where a negative case says what it means. The observed set and the declared set must match **exactly, in both directions**. Available names: `decision_signature_invalid`, `evidence_digest_mismatch`, `evidence_ref_absent`, `attester_address_mismatch`, `oracle_input_rebuild_differs`, `rebuild_digest_equals_declared` |
| `revocation` | declared ledger-side revocation of a delegation in the chain ⇒ `AUTH_DELEGATION_REVOKED`. Emptying the block FAILS the run |
| `verification_time` | the wall-clock instant to evaluate at; past the leaf expiry (`not_after`) ⇒ `AUTH_DELEGATION_EXPIRED` |
| `eip712_digest_hex` / `secp256k1_signature_hex` | recomputed and compared; the secp256k1 signature must RECOVER `roles.evm_attester.address`. Recovery runs only when the recomputed digest still equals `eip712_digest_hex` — over modified bytes it would return an unrelated address and prove nothing |
| `canonical_bytes_hex` / `canonical_sha256` / `ed25519_signature_over_canonical_hex` | JCS canonicalization + Ed25519 witness. The witness must verify under the **agent key derived from `seed_input`**, not under whatever key the vector declares, otherwise re-signing the bytes with an arbitrary key and declaring that key would pass |
| `seed_sha256_hex` / `roles.*` | bound to their derivations from `seed_input` in the same way |

Nothing in `verify.ts` branches on a fixture's `id` to decide what a case
means: renaming a vector (file, `index.json` entry and `fixture` field
together) leaves identical bytes passing.

Corpus membership is derived from `index.json`, never hardcoded. A vector that
is present but undeclared, declared but missing, declared twice, unreadable, or
whose `fixture` field disagrees with the id the index names it by — each is a
hard failure, not a skip.

`verify-consistency.ts` is a **same-implementation consistency** check, not an
independent verification: it re-uses the same vendored Insight builder the
upstream generator uses. It produces the "56/56 identical values" figure:
13 vectors × 4 commitments rebuilt from `oracle_input` (52) + digest +
secp256k1 on the two positive vectors (4). See `SOURCE.md` for what
independent recomputation exists.

## Vector catalog

| id | expected | what it exercises |
|---|---|---|
| pass / caution | allowed | clean PASS / CAUTION (both permitted verdicts) |
| danger / block | halt | negative oracle verdicts fail closed |
| expired-oracle | halt | validly signed but past the 600s window |
| tampered-oracle | halt | signed data modified after signing (UID mismatch) |
| wrong-signer | halt | attester address ≠ signer |
| authority-denied | halt | policy returned deny |
| sig-tampered | halt | decision receipt signature corrupted |
| digest-mismatch | halt | evidence_refs digest ≠ artifact |
| evidence-missing | halt | no oracle evidence ref at all |
| delegation-expired / delegation-revoked | halt | authority lapsed / revoked |

Replay / single-use enforcement is stateful and is **not** exercised by this
family at all: dispatch-time enforcement is out of scope here.

## Run

```bash
npm run verify:oracle-safety-check              # semantic verification, 13/13
npm run verify:oracle-safety-check-consistency  # same-implementation 56/56
npm run verify:oracle-safety-check-flips        # --flip-check: 5 declared
                                                # mutations, each of which must
                                                # FAIL (revocation emptied,
                                                # expectReasons bogus, expected
                                                # flipped, oracle_input.verdict
                                                # changed, expectReasons
                                                # emptied) — 5/5 detected
```

The flip check is scoped to those five mutations. It is not a claim that every
field in every vector affects the verdict.

All exit non-zero on any failure.

## Verification split

- EIP-712 digest and secp256k1 signer, 13 vectors; imokokok; Mode A; author-produced (author of the vectors and of the vendored Insight implementation); `verify.ts` in this directory, 13/13
- APS receipt layer (Ed25519 decision and intent signatures, canonical witness, delegation signature, linkage, continuity, leaf expiry, declared revocation) and composite-gate reasons, 13 vectors; imokokok; Mode A; author-produced (author of the vectors); `verify.ts` through agent-passport-system 4.5.1, 13/13
- same-implementation consistency, 56 values; imokokok; Mode A; author-produced (author of the vectors and of the vendored implementation); `verify-consistency.ts` in this directory, 56/56

These records are attributed per layer. Merge of this family is not an end-to-end verification or a family-level verdict.
