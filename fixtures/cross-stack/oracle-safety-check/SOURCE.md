# SOURCE — provenance of the oracle-safety-check vectors

This family exercises receipt and delegation evidence verification only;
dispatch-time enforcement is not exercised here.

## Upstream generator

The 13 vectors under `oracle-safety-check-v1/` are generated by the
**upstream generator** in the SDK repo:

- Repo: `aeoess/agent-passport-system`
- Commit: **`ba32424f40bd14d0ff7d20b9d66774022b5905d9`** (merge of PR #119 into
  `main`; parents `7159394a…` and `06d3d14f…`)
- Path: `fixtures/oracle-safety-check/generate-fixtures.ts`
- Seed: `aps-oracle-safety-check-fixture-v1` (SHA-256, per-role derivation —
  zero secret material)
- Baseline clock: `2026-08-25T00:00:00.000Z` (independent of wall clock)

The pin points at the **merged commit on `main`**, not at a PR head or a fork
branch, so it resolves for anyone who clones the SDK repo.

They are copied here per `docs/adding-vectors.md` (upstream first, then
mirrored) and verified against the **published** SDK package
(`agent-passport-system`), not deep imports into `src/`.

Regenerating from that pinned commit reproduces the committed family
**byte-identically**; the reproduction is part of `verify-consistency.ts`
(56/56) together with the corpus and witness bindings in `verify.ts`.

The three files are **byte-identical with the public reference implementation

production Insight is closed-source, so its source layout is out of scope for
the public evidence this suite can verify.

## Independence of the verification

`verify.ts` and `verify-consistency.ts` import the same vendored
`vendor/insight/` builder the upstream generator uses. What they demonstrate is
therefore **same-implementation consistency** — that the vectors are
self-consistent and regenerable — **not** an independent re-derivation from the
primitive formulas.

Independent recomputation lives outside these scripts:

- EIP-712 digests and signer recovery were recomputed from the vectors' own
  `eip712` data by the suite maintainer during review of PR #32, using ethers
  rather than viem and without importing the vendored builder. `tampered-oracle`
  and `wrong-signer` failed exactly where they should.
- The `verify.ts` inner-layer path is deliberately narrow for the same reason:
  it recomputes the digest and recovers the signer with viem primitives and
  compares against values the vector declares, rather than trusting a verdict
  the vendored builder returns.

Anything claiming more than same-implementation consistency from the scripts in
this directory is overclaiming.

## Dependency on the SDK package

`verify.ts` consumes the SDK as the **published package** (`agent-passport-system`)
— no deep imports into `src/`. The v2 receipt-core / authority-delegation
primitives it needs became public API in **4.5.0**, so upstream PR #119 no
longer carries an `src/index.ts` export hunk. The suite resolves the SDK from
the repository-level pin in `dependencies` (exact released version, currently
`4.5.1`); the earlier fork-branch git URL has been dropped, because a lab corpus
dependency has to sit on a released first-party artifact rather than a moving
branch.
