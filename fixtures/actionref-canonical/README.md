# Historical draft-01 action_ref canonicalization fixtures

This family exercises the historical four-field action_ref form of
draft-pidlisnyi-aps-01 section 4.1: SHA-256 over the RFC 8785 canonicalization
of {agentId, actionType, scopeRequired, timestamp}, with a second-precision
timestamp and no domain tag. Before canonicalization, each scope string is
normalized to NFC and the scopeRequired array is sorted by Unicode code point
(draft-pidlisnyi-aps-01 section 4.1). Code-point order differs from UTF-16
code-unit order for astral-plane characters; the astral-scope vector pins that
difference.

This is not the current native APS action_ref. The current native action_ref
is the "aps-action-ref-v2" profile (draft-pidlisnyi-aps-03 section 4.1,
draft-pidlisnyi-aps-04 section 5.1): eight snake_case members, a domain tag,
a millisecond timestamp, UTF-8 byte order and a duplicate-free scope_required.
This family does not test that form.

Six vectors:

- Four draft-01 conformance vectors: `plain-single-scope-ascii` (plain
  single-scope ASCII), `unsorted-multi-scope-ascii` (unsorted multi-scope
  ASCII), `nfd-scope-normalizes-to-nfc` (an NFD scope that normalizes to NFC)
  and `astral-scope-orders-after-bmp-high` (an astral-plane scope ordering after
  a U+E000..U+FFFF scope). Generated by the agent-passport-system TypeScript
  reference and cross-verified byte-identically by the Go implementation.
- Two implementation-specific negative tests: `negative-duplicate-scope-raw`
  and `negative-duplicate-scope-nfc-collision`. They test behavior that
  agent-passport-system added in commit
  ca7413c9124cda8e2d6dd4e959bb731731771e7f (2026-07-25): a scopeRequired array
  holding two elements equal after NFC is rejected with
  `duplicate_scope_required` rather than deduplicated. That commit is evidence
  of implementation behavior only. Draft-01 does not define duplicate scopes as
  invalid, so rejecting these two inputs is not a draft-01 conformance
  requirement.

These vectors carry expected action_ref values rather than the
canonical-bytes contract fields. Both suite runners recompute action_ref for
each input, NFC-normalizing every scope string, sorting scopeRequired by
Unicode code point, then JCS + SHA-256, and assert the recomputed hex and
canonical scope order match the recorded values (TS: computeNativeActionRef in
runners/ts/verify.ts; Go: checkActionRefVectors in runners/go/main.go via the
agent-passport-go actionref package). For the two negative tests, both runners
instead assert rejection with the recorded rejection_kind. External
implementations verify the same way.
