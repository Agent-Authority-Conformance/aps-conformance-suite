## What this run checks and what it does not

For each vector it rebuilds the EIP-712 typed-data digest from `envelope.oracle.eip712`
(domain, types, primaryType) and `envelope.oracle.data`, compares it to `envelope.oracle.uid`,
recovers the secp256k1 signer from `(uid, signature)`, and compares it to the declared
`envelope.oracle.attester`. It does not check the APS receipt layer (Ed25519 decision
signatures, delegation records, evidence references, canonical witness); those are checked by
the family's own runner and by the suite maintainer's clean-clone reproduction, and the
maintainer authored the SDK that layer uses, so that check is not independent under this
document's definition.

Expected divergences by design: `tampered-oracle` edits `consensusPrice` after signing, so the
rebuilt digest differs from the declared uid; `wrong-signer` declares a different attester
under an unchanged signature, so the recovered signer differs from the declaration. Every
other vector matches on both.
