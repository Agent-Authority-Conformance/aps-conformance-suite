## What this run checks and what it does not

The three documented family commands are run as-is (family README, "Run" section):

- `npm run verify:oracle-safety-check` exercises `verify.ts`: for each of the 13 vectors it rebuilds the oracle data from `oracle_input` (including the four ABI-keccak commitments), recomputes the EIP-712 digest and recovers the secp256k1 signer against `roles.evm_attester.address`, verifies the Ed25519 canonical witness under the agent key derived from `seed_input`, enforces the exact `expected` / `expectReasons` / `expected_sub_results` match, and the composite-gate reason set. It does **not** run the SDK's full delegation-chain verification (`verifyAuthorityDelegationChain`); authority attenuation (`SPEND_WIDENING`) is out of scope by design (stated in the family README).
- `npm run verify:oracle-safety-check-consistency` runs `verify-consistency.ts`, a same-implementation consistency check (52 commitment rebuilds + 4 positive digest/signature) producing 56/56.
- `npm run verify:oracle-safety-check-flips` runs `verify.ts --flip-check`: five declared field mutations, each must fail the run; all five detected.

This is a Mode A reproduction: it reuses the documented verification path. It is author-produced, not independent, because the runner, the vectors and the vendored Insight implementation are all mine. The independent EIP-712 recomputation is Tymofii's `interop/ethers-oracle-safety-check-9b4ffee/` report (Mode B); the composite-gate reason semantics still await a separate external run (per PR #32 review).
