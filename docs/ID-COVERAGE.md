# draft-pidlisnyi-aps-03 requirement coverage inventory

This table records which normative requirements of the published Internet-Draft the fixtures and runners in this repository exercise; it makes no claim that a passing run validates the draft.

Draft: `draft-pidlisnyi-aps-03-PUBLISHED.txt`, sha256 `59b9547a20c6d514eceb97d169b92b2f9c70a231f5b914e8fc1b478c7f359fca`.
Suite: commit `b0bf645c4f1deb3e7a26411295de6fda98fb80b4` (revisions 3, 4 and 5). Revisions 1 and 2 were pinned to `b46568e8947291e553c6392403226e8d05be31d2`.

Requirement extraction: every sentence in the draft body carrying an RFC 2119 keyword (MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, NOT RECOMMENDED, MAY, OPTIONAL), excluding the definition in Section 1.1. Sections 1, 1.1, 3.1, 3.4, 6, 8, 11, 12, 13, 14, 7.2 and Appendix A carry no such sentence and so contribute no rows.

SCOPE. This inventory covers the whole of draft-pidlisnyi-aps-03 and nothing else. It is not a map of any other property set: work scoped to a particular counterparty or working group, including the CoSAI seam properties, is a different audience with a different question and does not appear in this table. Mixing the two would let a reader take a row about one as coverage of the other.

Status definitions, as proposed in Agent-Authority-Conformance/aps-conformance-suite#150 (comment window closes 2026-10-11).

- **EXERCISED:** named vectors reach assertions that would fail if the implementation under test violated the requirement, covering every clause of the requirement, on the object or construction the requirement specifies and under the same normative basis.
- **PARTIAL:** a named vector reaches an assertion relevant to the requirement, but the evidence falls short of EXERCISED. Examples include a rejection rule whose vectors never present the case the rule forbids, an assertion that reaches only some clauses of the requirement, or an assertion that checks related behavior on a different object, form or normative basis. The row note must state that difference.
- **NOT EXERCISED:** no assertion checks the requirement. Related fixture data alone does not count, whether or not a runner loads it.

A **named vector** is an identified fixture case, or an input constructed by a runner and identified in its output. It counts only when a documented suite runner at the pin reaches the assertion. An assertion that is skipped or disabled at the pin does not count.

The status describes suite coverage, not a conformance verdict on an implementation.
